# Findings — 0.1 Postgres schema + AGE extension (issue #2)

Branch `feat/0.1-postgres-age-schema`. Reviewed by `security-auditor` and
`code-reviewer` in parallel on the same changeset, then re-verified against a
real database. Evidence for every claim below is in `logs/session-20260905.md`.

## Runtime evidence

Four checks, all passing on a fresh volume (`scripts/verify-db.sh`, exit 0):

| Check | Result |
|---|---|
| db service starts clean (healthy, no errors in the init log) | PASS |
| `SELECT * FROM ag_catalog.ag_graph;` shows the graph | PASS — `osint`, graphid 17039 |
| unqualified objects are created in `public` | PASS |
| `cypher()` resolves in a fresh session, no `LOAD`, no `SET` | PASS |

`init.sql` replayed by hand twice against an already-initialised database:
both OK, graph count stayed 1. The idempotency claim in the file is verified,
not asserted.

## Defects found by running it, not by reading it

**1. `apache/age:latest` moved to a Postgres 18 base and the stack stopped
starting.** The image relocated `PGDATA` to `/var/lib/postgresql/18/docker` and
now refuses a mount at the old `/var/lib/postgresql/data` path — the mount the
repo's compose file already had. Fixed by mounting the parent per upstream
guidance, and by pinning `apache/age` to `release_PG18_1.8.0` plus its digest.
This is why the image is pinned, not a theoretical hardening step.

**2. `"$user"` on the search_path resolved to the AGE graph's own schema.** The
first fix for the search_path finding below used the auditor's recommended
`"$user", public, ag_catalog`. The new regression guard immediately failed:
`current_schema()` returned `osint`, not `public`. `create_graph('osint')`
creates a schema named after the graph, and the default role is also `osint`
(`POSTGRES_USER`), so `"$user"` — which normally resolves to nothing — resolved
to the graph's schema. Application tables would have been created inside it,
where `drop_graph('osint', true)` removes them. Final path is
`public, ag_catalog`, with `"$user"` omitted and the reason recorded in the file.

## Review dispositions

### Fixed in this changeset

| Severity | Finding | Disposition |
|---|---|---|
| HIGH | `search_path` pinned `ag_catalog` first, making it the creation schema for every later migration | Fixed — `public, ag_catalog`, ag_catalog last. Guarded by a `current_schema()` assertion, which is what caught defect 2 above |
| MEDIUM | `apache/age:latest` unpinned, no update channel | Fixed — pinned to tag + digest; `docker` ecosystem added to `.github/dependabot.yml`. Tag kept alongside the digest because Dependabot cannot bump a digest with no tag to compare against |
| MEDIUM | `session_preload_libraries` locks out every connection if the library ever fails to load | Accepted with mitigation — the setting stays (the alternative is `LOAD 'age'` in every connector). The digest pin removes the drift path, and the `RESET` recovery command is documented at the setting |
| MEDIUM | `verify-db.sh` log check fails open — greps the empty output of a failed command and reports PASS | Fixed — capture, assert non-empty, then grep |
| MEDIUM | `down -v` safety was incidental and unguarded | Fixed — fails closed if `$PROJECT` collides with the default project or if the compose file ever names/externalises its volumes; stderr no longer discarded |
| MUST-FIX (reviewer) | Log grep false-positives on the benign `FATAL: the database system is starting up` | Fixed — that line is filtered before the error scan |
| SHOULD-FIX | `compose ps -q` misses an exited container, so a crash-loop waits the full timeout reporting a misleading status | Fixed — `ps -aq`, plus an empty-`$cid` guard |
| SHOULD-FIX | bare assignment under `set -e` aborts before the intended diagnostic | Fixed — every query is wrapped and reports its own failure |
| LOW | `grep -q "$GRAPH"` also matches the `namespace` column | Fixed — server-side `count(*) ... WHERE name::text = 'osint'` |
| LOW | missing `init.sql` makes Docker bind-mount a root-owned directory, silently | Fixed — pre-flight `[ -f app/db/init.sql ]` guard |
| LOW | unrecognised argument silently ignored, then teardown runs | Fixed — `case` with usage and exit 2 |

### Closed with evidence

| Finding | Resolution |
|---|---|
| INFO: PG major and host auth method undeterminable while the tag is unpinned | Determined after pinning: PostgreSQL 18.6, `password_encryption = scram-sha-256`. `has_schema_privilege('public','public','CREATE')` is `false`, so the PG&lt;15 world-writable-`public` concern does not apply and no `REVOKE` is needed |
| Whether `ag_catalog` last still resolves AGE | Verified — `cypher()` runs in a fresh session with no `LOAD` and no `SET` |
| Whether `LOAD 'age'` is redundant | Confirmed necessary for the init session itself; `CREATE EXTENSION` does not run `_PG_init()` in the current backend |
| Whether `down -v` under `-p` can reach the real `db_data` | It cannot — compose namespaces bare volumes per project. Now also guarded rather than left incidental |

### Noted, no action

`pg_hba.conf` ships `trust` for the container's own loopback (stock postgres
image behaviour). Not a new exposure: anything executing inside the container
can already read `POSTGRES_PASSWORD` from the environment. External connections
match the appended `host all all all scram-sha-256` rule.
